## Q1：当 finishing tag 的值超出 Search Tree(Trie) 所能表示的值范围，应当如何处理？

**A：** 答案不是"溢出报错"，而是**架构上根本不让它发生**——通过 WFQ 计算侧的周期性回绕 + 树侧的及时删除来配合解决。

### 1. 核心机制：WFQ 计算电路做周期性回绕（wrap-around）

树本身只有有限的表示范围（实现中为 3 层、12-bit 字，即 0–4095）。为防止 finishing tag 随时间无限增大，WFQ 策略在 tag 值达到一个有限最大值后**将分配值重置为零**。到回绕发生时，先前分配的最小一段 tag 早已被服务并移出系统，这些数值可以重新使用（论文 III-A 节，"removing entries from the tree" 一段）。

### 2. 为什么回绕是安全的：活跃值域只是一个"滑动窗口"

任意时刻，新产生的 tag 最小值大于当前最低 tag 值、最大值在当前最高值附近，分布近似正态且随时间整体前移（Fig. 6）。也就是说系统真正占用的只是全范围中的一段窗口，而非整个值域。

### 3. 配套操作：删除已"落在窗口之后"的 tag marker，回收树空间

随着 tag 被服务，位于当前最低 tag 值之后的值段被腾空，**树中对应的 tag marker 必须删除**，这样当 WFQ 计算回绕后再次到达这段范围时，树的该部分可以复用。实现上很高效：顶层是单个 16-bit 节点，把总值域均分为 16 段；当某段刚移出当前最低 tag 值的范围时，从该 bit 生出的**整棵子树被一次性隔离并删除**——批量回收，不需要逐个 tag 操作。

### 4. 若确实需要更大范围：硬件扩展选项

设计是可配置的：把节点位宽从 16-bit 扩到 32-bit（每层字面量 4→5 bit），树即可处理 15-bit 字（0–32767），代价是地址转换表从 4k 扩到 32k 项。论文明确说没有任何实践上的障碍，只是面积成本。

### 边界补充：重复 tag 与范围溢出是两个不同维度的问题

若 WFQ 计算精度超过树的粒度，tag 会被舍入，可能出现**相同值的重复 tag**——由链表的顺序存储特性以先来先服务（FCFS）方式解决，转换表只记录最新的重复项（第二篇 3.2.3 节）。

> 范围靠回绕，粒度靠舍入 + FCFS。

## Q2：将树的参数设定为 3 层、node width 16-bit，举一个具体例子说明 finishing tag 如何周期性回绕

**A：**

### 参数回顾

- 3 层 × 4-bit literal = **12-bit tag**，值域 0–4095
- 顶层单个 16-bit 节点将整个值域均分为 **16 段、每段 256 个值**

### 一句话例子

> 某段时间 WFQ 计算电路给到达的包依次分配 finishing tag 3900、3920、…、4094、4095，而此刻系统中最低的活跃 tag 已是 3900——0–3899 的旧 tag 早已全部服务出队，顶层节点 bit0～bit14 对应的整段子树也已被一次性删除回收；于是下一个包不会再分配 4096（超出 12-bit 表示范围），而是**从 0 重新开始**——例如分到 tag = 10（三层 literal 依次为 0000 / 0000 / 1010），它恰好落在早已腾空的 0–255 段，树可以正常写入这个 marker 并复用该段存储，这就是一次周期性回绕。

### 按时间线展开

1. 活跃窗口随服务不断前移，最低 tag 越过某段边界（256 的倍数）时，刚落在窗口之后的整段子树被批量删除；
2. 分配序列逼近上限：… 4093、4094、4095；
3. 到达 12-bit 上限 → 下一次分配回绕为 0、1、2…，写入已清空的低位段，循环往复。

### 实现层面的提醒（论文未细述的边界）

回绕刚发生的一小段时间内，新的小数值 tag（如 10）会和尚未出队的旧大数值 tag（如 3900–4095）在树/链表中并存——数值上 10 < 3900，但逻辑上旧包应先被服务。论文只保证了此刻低位段是空的（写入安全）；如果要在硬件里实现这个排序电路，服务顺序需要用**环形比较**（以当前最低活跃 tag 为基准）或额外的**回绕计数**来维持正确。
