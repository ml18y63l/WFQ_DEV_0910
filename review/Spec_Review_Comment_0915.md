## 3. 逻辑层面发现

### L-1 §10.7 对 I=4 不可行的论证不完整

**原文**："若只将 I 改为 4，旧插入 E4 的 L3 写将与新操作 E0 的 L3 读重叠，而且新准入不能依赖沿后才完成的提交状态。"

**问题**：该理由描述的是"保留 5 级流水、仅缩短接受间隔"的解读（此时旧插入 L3 写在其局部 E4）。但 §2.2 规定全部常量由 I 派生：I=4 时 C=I-1=3，旧插入的 L3 写在 E3、与新操作 E0 读（全局 4）并不同沿——按字面派生，原文理由不成立。字面派生下真正的首要矛盾是 **B=I-4=0**：备用叶读与精确叶读落在同一沿（L3 1RW 冲突），且备用地址依赖 E0 才读出的精确叶 q，同沿不可得。结论（I≥5）本身正确，两种解读均不可行，但现有文字只给了其中一种且与派生规则表面冲突。

**建议**改写为完整论证：FAST5 依赖链 E0 精确叶读 → E1 备用叶读 → E2 TT 读 → E3 NEXT 读 → E4 提交需要 5 个互异的接受后沿，且 B=I-4≥1 要求 I≥5；若按 §2.2 派生 I=4，则 B=0 导致备用读与精确读同沿冲突且地址不可得；若保留 5 级流水仅缩间隔，则新事务 E0 的 L3 读与旧插入 E4 的 L3 写同沿冲突、准入无法引用当沿才提交的状态。

### L-2 fault_code 2 应显式枚举备用路径中间层矛盾

**问题**：§7.3 依赖不变量保证"bB 命中 ⟹ B 叶非空"、"aC 命中 ⟹ L2[aC] 非空 ⟹ bC 命中"。违反时的行为由 §13.2 code 2 覆盖，但现有枚举"有效备用叶为空"只明确到**叶层**；"aC 命中而 bC 未命中"（L1/L2 矛盾，备用地址无法形成）未被点名。F24 要注入 TT/RC/marker 损坏，验证环境需要确定的期望编码；若 RTL 把该情形静默处理为"无同代前驱"，将得到错误的链表位置而非 fault。

**建议**将 code 2 枚举细化为（或等价补充）：① 有效同代前驱（含 exact）的 TT.valid=0；② trie_exact 与本事务保存的 old_RC≠0 不一致；③ bB 命中但 B 叶 q 为空（L2/L3 矛盾）；④ aC 命中但 bC 未命中，即 L2[bank,aC]==0（L1/L2 矛盾）；⑤ C 备用叶 q 为空；⑥ 出队精确路径 marker 缺失（RC>0 而叶位为 0）。

## 4. 实现障碍确认与排序

### O-1 出队 E0→E1 单拍提交（首要风险，确认）

四个同步读（RC/L3/DATA/NEXT）的 q → RC 递减与边界、并行 ==onehot 判空/清位级联、下一头 epoch 检查（code 4）、FREE 写、head/bank/base 更新、响应 FIFO push，全部在一个周期内完成并在 E1 提交。规格已声明（§10.3"PIPE6 不会自动放宽该路径"）并给出化简（§7.7 并行等值比较，本次复核确认等价性前提表述正确）。评审确认其为全设计第一关键路径；失败时的出路只有 §15.3 的降频或另立规格。

### O-2 插入 E_C 末级单拍（第二风险，确认）

E_P→E_C 一个周期内：NEXT q → successor 字段补齐 → 局部检查（含 successor 边界类 code 3）→ 直接驱动 DATA[n]/NEXT[n]/RC/TT/必要 L1/L2/L3 的写口 D/WE 及 head_cache/bank 寄存器 D。规格明确禁止再加一拍（§10.2、附录 A 注、附录 B.5），且 **PIPE6 不缓解该公共路径**（§15.3 已自认）。积极面：TT-valid/trie_exact/RC 边界等检查已在 E_P 随主体锁存，末级只剩 successor 相关检查——这是正确的负担前移，评审确认该划分合理。若 STA 失败，先按 §15.2 优化选择器/扇出，不得隐式加拍。

### O-3 E0 输入直达路径（集成约束，确认）

E0 的 RC/L3/FREE 读地址与 FAST5 上层查找的 L2 mux 选择直接来自握手 payload（引脚）+ free_count + 准入门控：epoch 窗口比较 → 资源/RR → read_en/地址建立，全部在接受沿前组合完成。规格已要求 input delay 与接受门控约束（§15.2 末行）。对 300 MHz ASIC 目标，这决定上游必须紧邻寄存驱动，集成方需在约束中为该路径单独分配预算。注意 payload 在 E0 捕获后，E0→E1 的组合查找用的是已捕获值（§10.2 已写清），两条路径（引脚→E0 地址；E0 捕获寄存器→E1 备用地址）是独立的关键路径，约束应分别覆盖。

### O-4 FAST5 前视网络（面积/布线，确认）

两 bank 共 32 个 16-bit MAX 编码器常开 + aC 控制的 32:1 选择，再加 L1/L2 寄存器的多路组合扇出。动态功耗有界（输入仅在 L2 写沿翻转，≤每 I 拍一次），主要是面积与布线障碍。规格已要求综合报告单列（§15.1）并给出 PIPE6 替代（仅所选字的 MAX 通路）。确认保留，无需修订。

### O-5 "写必须在调度沿物理生效"的宏假设应明示

全设计最紧的跨事务读边距为 1 拍：前一插入的 E_C 写（RC/TT/DATA/NEXT[n]/必要 Trie）落在 t-1，下一事务的 E0 读在 t 发出。这对标准同步 SRAM（写在调度沿生效）成立。但部分工艺库宏提供可选的**内部写流水/延迟写**模式；若选用，t 沿读将返回旧值——除非把该写保留在 pending 转发集合直至物理完成。§15.1 只禁止了读侧隐藏输出级（"无隐藏输出级"），未明示写侧。建议在 §6.4 或 §15.1 补一句："各同步存储的调度沿写必须在该沿对后续读物理可见；不得选用带内部写流水/延迟写模式的宏，若工艺仅提供此类宏，须将相应写纳入 pending 转发集合直到物理写完成，并重新验证端口表。"

### O-6 同沿 retire/enqueue（低）

全局 t+I+1 沿可能同时发生 T0 退休与 T1（出队）提交，上下文控制器须支持同沿释放/占用（§10.4 已列要求）。实现时注意 retire 与 enqueue 对同一上下文池的指针操作需一拍内完成，属常规设计点，提示即可。

## 6. 本次独立复核通过项

1. **派生常量一致性**（§2.2 ↔ §10.2/§10.4）：B/T/P/C/PATCH/R 对 I=5/6 的全部取值与排程表逐项吻合；T2 最早接受 = 2I；RR 等待界 2I-1 = 9/11。✓
2. **逐沿端口重放**：Insert/Insert、Insert/Extract、Extract/Insert、Extract/Extract 四类相邻组合下，L3 每沿至多一次访问且无同沿 R+W；其他 RAM 每沿 ≤1R+≤1W；与模型 56 组排程检查互证。✓
3. **1-edge 边距族**：前一插入 E_C 写（t-1）→ 下一事务 E0 读（t）覆盖 RC/L3/DATA/NEXT[n]/L1/L2 全部存储，同步 SRAM 下成立；唯一同沿冲突族是 E_I 的 NEXT 写 vs 新出队 E0 读（可能同址），由同沿写总线优先 + overlay 至退休覆盖（模型 raw_hits 53/54 次实测命中）。✓
4. **提交沿互斥性（本次新推导）**：任意两事务的提交沿永不重合——插入提交在 a+I-1、出队在 a'+1，重合需接受间距 = I-2 < I，矛盾。因此 L1/L2"每层每沿至多一个字写"由调度自动满足，提交控制器无需仲裁两个同沿提交。建议可作为规格附注或断言（现断言 1/2 已隐含）。✓
5. **快照有效性**（§11.2）：接受到提交区间内不存在其他提交沿（前一事务最晚在 t-1 提交、后一最早 t+I），old_root/old_parent/old_leaf/old_RC 快照与 E_C 更新之间无丢失更新窗口。✓
6. **指针生命周期**（§11.5）：t+2I > t+I+1 对 I=5/6 成立；插入最大存活 I+1 < 2I，两上下文充分。✓
7. **资源数值**：475,136 同步位 + 544 寄存器位 = 475,680 bit ≈ 58.07 KiB；较 V1.0 减 16,896 bit；各 RAM 深宽公式（含 B^(level-1) 修正版）全部复算正确。✓
8. **前驱算法**：A/B/C 三类对 y≤x 的不重不漏划分、唯一备用叶的优先级选择、F07/F08/F09 期望值——模型 1,163,264 组合（含 FAST5 前视与 PIPE6 分割两种 profile 的等价性）与 0911 轮独立复算双重印证。✓
9. **模型代码保真度**（逐行审查 [wfq_v11_check.py](model/wfq_v11_check.py)）：同步读 due≥t+1 强制、同沿写总线优先于 overlay/RAM、overlay 保留至退休沿、插入 NEXT[p] 物理写延迟至 E_I、FREE/响应信用守恒每沿断言、check() 全结构对比（链表序/RC/TT/Trie/FREE 唯一性/bank 区段）——与规格 §6/§9/§11 语义一一对应；附录 C 声明的数字与实际运行输出一致。✓
10. **0911 评审决议回归**：参数公式（G-3 修正版）、响应沿语义（§4.3 E1 沿后 valid/E2 最早消费）、fault 同沿优先级、F24 注入约定（含 overlay 遮蔽提示）、DFT 归属（§1.2）、empty 组合比较合法性（§4.4）、init R8191/R8192/R8193——全部落入 V1.1 正文，无遗漏。✓

## 7. 模型覆盖边界（供验证计划对照）

附录 C 已声明模型不含 fault 注入、电气时序、全参数组合与第 14 节全部验收。本次代码审查补充确认模型**亦未覆盖**以下功能路径（应由 §14.3 定向用例承担，建议在附录 C 补一句以免误读）：

1. epoch 窗口拒绝与第三代背压（模型激励始终生成合法 epoch，F16 路径未进模型）；
2. 空队列后任意 epoch 重建窗口（F01/F15 尾段）;
3. RR 仲裁与 2I-1 等待界（模型为单请求流）；
4. 初始化序列本身（模型从已初始化状态开始）。

## 8. 结论与放行建议

V1.1 的单副本存储组织、II=5/6 完整排程、末级提交机制和生命周期证明在规格层面自洽，未发现会导致错误功能行为的逻辑漏洞；两处文档级缺口（L-1 论证补全、L-2 故障枚举细化）均为文字修订，不阻碍启动 RTL。

建议顺序：

1. **启动前落规**：L-1、L-2、O-5（一句话宏约束）、E-1～E-3，预计半天内完成。
2. **RTL 编码时优先做时序预算**：O-1（出队 E1）与 O-2（插入 E_C 末级）是两条决定成败的单拍路径，编码前先做逻辑划分与扇出预估；O-3 的输入路径约束写入 SDC 骨架。
3. **配置决策依据**：F30 双配置同工艺/PVT 综合对比，按 f5 > (5/6)·f6 判据选择，不预设 FAST5 优胜。
4. 契约冻结项（§16.2）不变：任何对 I、提交沿、L3 端口组织的"顺手优化"都属 §16.3 的重新设计。
