# f_clk/4 吞吐可行性评估

日期：2026-09-15。当前设计基线：`Design_Spec_V1.2.md`。当前 RTL 状态：阶段 1 基础模块已完成。

**结论：V1.2 原排程不能直接配置为 I=4；增加每个 L3 叶的 4-bit 最大有效索引摘要后，可以构造保持单份、单端口同步 L3 的 I=4 排程。该候选已通过本文算法与周期模型检查，实际 RTL 和时序可行性尚待验证。**

本次只新增评估文档和模型，没有修改 V1.2、现有 RTL 或实施计划的设计基线。采用 I=4 需按 V1.2 §16.3 更新后续规格。

## 1. 为什么直接改常数不成立

需要区分两种修改：

| 修改方式 | 首要问题 |
| :--- | :--- |
| 继续按 V1.2 §2.2 派生所有阶段，将 I 设为 4 | E_B=I−4=0，精确叶和备用叶都要求在 E0 读同一物理 L3 端口；备用选择还依赖 E0 之后才返回的精确叶结果 |
| 保留 FAST5 的 E0/E1/E2/E3/E4 搜索及提交，只把下一次接受提前到 E4 | 旧插入 E4 的 L3 写与新事务 E0 的 L3 读冲突；旧提交和新准入同沿，还需新的 head/cache/bank/容量视图转发 |

当前 `wfq_sync_ram_1rw.v` 会明确拒绝同拍读写，因此第二种改法会触发实际接口冲突。

现有依赖链为：

```text
E0 精确 L3 读
 → E1 备用 L3 读
 → E2 TT 读
 → E3 NEXT 读
 → E4 提交
 → E5 最早下一次接受
```

这解释的是**当前架构的限制**。一次最坏路径插入需要 L3 两读一写，共三个端口访问，四拍的平均端口预算并未耗尽；I≥5 并非所有单端口 Trie 实现的理论下界。

不能直接将既有 `model/wfq_v11_check.py` 的 `schedule()` 参数改成 4 来证明可行：其阶段用字典键表示，E0 与 E_B 同为 0 时会覆盖原有访问记录。新增模型使用独立事件列表，保留同沿的全部访问。

## 2. 首选候选：L3 叶最大索引摘要

对全部 512 个物理 L3 叶维护：

```text
leaf_max[bank,a,b] = MAX(L3[bank,a,b])，当叶非空时
leaf_max[bank,a,b] = 0，                 当叶为空时
```

每项只存 4-bit 索引。有效性继续取自原有 L2[bank,a][b]，不额外保存 valid，也不能将索引 0 当作空叶编码。L3 仍保存完整 16-bit bitmap，使用一份 512×16、read latency=1 的 1RW SRAM。

摘要采用**寄存器组合读取**。它是新增派生状态，不是无成本的连线；也不是复制整张 L3。不能在 E0 后从同步 L3 现读现算该摘要，否则无法消除依赖。

原算法中 A 路径仍须对精确叶执行 LE(c)，因为 MAX 无法代替任意 query 的 LE。B/C 的备用前缀由 L1/L2 确定，而其末级 literal 只需要该叶的 MAX，正好可由摘要提前提供。

因此 E0～E1 内同时得到：

- A：精确叶同步 q 经 LE(c) 得出。
- B：L2 的 LT(b) 给出 bB，摘要给出 cB。
- C：根 LT(a) 与 L2 组合前视给出 aC/bC，摘要给出 cC。

按 A>B>C 选出完整 pred_tag，在 **E1 发起 TT 读**。

### 2.1 保留备用叶读取作为并行校验

推荐保留 E1 的备用 L3 读取，并与 TT 读取并行：

```text
                     ┌─ TT[pred_tag] 同步读 ──→ E2 获得前驱指针 p
E1 已有 pred_tag ─────┤
                     └─ 备用 L3 同步读 ───────→ E2 校验非空及 MAX 等于摘要
```

只有备用叶校验通过、TT link 有效且指针范围合法，E2 才允许读 NEXT[p]。校验不通过应进入 metadata fault（建议沿用 code=2），不能回退搜索、重试或提交。这样正常操作保持固定时延，同时保留对实际备用叶内容的检查。

TT 读地址来自已确定的摘要候选；它在校验完成前只是无副作用的元数据读。NEXT 节点解引用及最终提交必须等待校验。精确叶也可在返回后检查其摘要一致性；与更新相关的旧 bitmap 必须保存为独立快照。

### 2.2 摘要更新和初始化

摘要与对应 L3 bitmap 在**同一逻辑提交沿**更新，保持不可分割的状态变化。可以根据已保存的精确叶计算 `MAX(new_leaf)`：

- 新键插入导致 marker 变化：更新该叶 bitmap 及摘要。
- 重复键插入或非最后引用删除：bitmap 和摘要均保持。
- 最后引用删除：清除 marker，再根据 new_leaf 更新摘要；空叶摘要置 0。
- epoch bank 清空和重用：沿用精确删除，最后键清理同时恢复相关摘要，不做运行期整 bank 清表。

插入阶段可提前计算 new_leaf 和 new_max，不应将所有摘要计算堆到 E3 提交末级。出队仍在 E1 提交，增加的摘要更新路径需单独检查时序。

初始化可复用 L3 的前 512 个清表地址并行清摘要。默认仍是 8192 个写沿加一个 guard；增加这些寄存器不需要增加扫描周期。可使用独立 512×4 寄存器模块，或把每个 L2 父节点的 16 项摘要就近组织为 64-bit 寄存器字段；两种实现的信息量相同。

## 3. I=4 完整候选排程

| 动作 | 当前 FAST5 | 摘要候选 FAST4 |
| :--- | :--- | :--- |
| 接受；精确 L3 / RC / FREE 读 | E0 | E0 |
| 备用 L3 读 | E1，结果决定后续 TT 地址 | E1，结果用于校验已发起的 TT 地址 |
| TT 读 | E2 | **E1**，与备用 L3 并行 |
| NEXT[p] 读、锁存提交主体 | E3 | **E2**，先通过备用叶/TT/指针检查 |
| 插入逻辑提交 | E4 | **E3** |
| NEXT[p] 修补、最早下一次接受 | E5 | **E4** |
| 插入写回完成 | E6 | **E5** |
| 出队提交 / 写回完成 | E1 / E2 | E1 / E2 |

相应常量不能继续无条件复用旧 `E_B=I−4` 公式。对 FAST4：备用 L3 校验读与 TT 读都为 E1，NEXT 读 E2、提交 E3、修补 E4、写回完成 E5。若后续同时支持 4/5/6，须分别定义合法阶段映射。

### 3.1 端口与生命周期

| 存储 | FAST4 插入 | 出队 | 相邻事务约束 |
| :--- | :--- | :--- | :--- |
| L3 1RW | R:E0、可选 R:E1、必要 W:E3 | R:E0、必要 W:E1 | 上次最晚写 E3，下一事务最早读全局 E4，无冲突 |
| TT 1R1W | R:E1、W:E3 | 必要 W:E1 | 每沿最多一读一写 |
| RC 1R1W | R:E0、W:E3 | R:E0、W:E1 | 每沿最多一读一写 |
| DATA 1R1W | W:E3 | 下一头 R:E0 | 每沿最多一读一写 |
| NEXT 1R1W | R:E2、新节点 W:E3、前驱 W:E4 | 下一头 R:E0 | 保留旧修补与新出队同址读的旁路 |
| FREE 1R1W | R:E0 | W:E1 | 每沿最多一读一写 |
| L1/L2/leaf_max 寄存器 | 必要 W:E3，组合读 | 必要 W:E1，组合读 | 每组每沿最多更新一个叶/父/根目的项 |

旧插入在全局 E3 提交，下一次 E4 接受仍读取已经提交的逻辑状态，保留 V1.2 的“提交早于下一次接受”性质，无需新增同沿准入与提交的整组状态旁路。

最紧插入→出队序列为：旧插入 E3 提交，E4 NEXT 修补/新出队接受，E5 旧写回完成/新出队提交，E6 新出队写回完成。现有 NEXT 同址旁路原则继续适用；响应产生和消费的相对时序不变。

插入上下文在 E5 释放，下一笔在 E4 进入，最多两笔上下文；第三笔最早 E8。旧节点修补在 E4，新出队 E5 才释放原头，下一次可重分配最早 E8，节点生命周期关系仍成立。

模型还检查了 4、5、6、7 拍的任意相邻接受间隔，未依赖所有接受沿固定对齐到全局四拍边界。

## 4. 存储、面积和时序代价

默认配置新增摘要状态：

```text
2 banks × 256 leaves/bank × 4 bit = 2048 bit = 256 byte
```

| 项目 | V1.2 | FAST4 摘要候选 |
| :--- | ---: | ---: |
| L1/L2 原有寄存器状态 | 544 bit | 544 bit |
| 新增叶摘要寄存器 | 0 | 2048 bit |
| 上述 Trie 寄存器合计 | 544 bit | 2592 bit |
| L3 SRAM 数据位 | 8192 bit | 8192 bit，仍单份 1RW |
| 规格 §6.2 相同口径的状态位合计 | 248352 bit | 250400 bit，约 30.57 KiB |

按该口径总位数增加约 **0.825%**，但这是寄存器位数增加，不代表综合面积只增加 0.825%。寄存器、4-bit 选择网络、校验逻辑和布线成本需要综合报告；新流水字段尚未包含在这份简化存储位数估算内。

必须检查的路径：

1. E0～E1：精确 L3 q→LE；L1/L2 前视→摘要选择；A/B/C 选择→TT 地址建立。可预计算每个父节点的最高子分支及相应摘要，再由根选择，避免无必要的串联大 mux。
2. E1～E2：备用 L3 q→MAX/摘要比较，以及 TT q→valid/range 检查，两者共同形成 NEXT 读使能。
3. E2～E3：NEXT q 与既有提交末级。提交主体仍须提前寄存。
4. 出队 E0～E1：原有删除/缓存更新，加上摘要更新和局部一致性检查。

“组合读取 0 拍”不代表组合延迟为零；当前没有 FAST4 RTL、具体宏替换或 STA，不能据模型直接承诺频率。

## 5. 吞吐收益的正确比较

在请求、容量、epoch 和响应信用均满足时：

```text
FAST4 聚合操作率                 = f4/4
均衡插入、出队的各方向操作率      = f4/8
每包一次插入加一次出队的包服务率  = f4/8
FAST4 优于 FAST5                 ⇔ f4 > 0.8×f5
FAST4 优于 PIPE6                 ⇔ f4 > (2/3)×f6
```

同频下 FAST4 比 FAST5 的聚合操作率增加 25%，比 PIPE6 增加 50%。例如：

| 实际可达时钟 | FAST5 聚合 | FAST4 聚合 | FAST4 均衡包服务率 |
| :--- | ---: | ---: | ---: |
| 两者均 250 MHz | 50 Mops/s | 62.5 Mops/s | 31.25 Mpps |
| 两者均 300 MHz | 60 Mops/s | 75 Mops/s | 37.5 Mpps |
| FAST5=250 MHz、FAST4=200 MHz | 50 Mops/s | 50 Mops/s | 25 Mpps |

表中频率是比较示例，不是测量结果。FAST4 若因组合逻辑增加而降频超过 FAST5 的 20%，就失去对 FAST5 的净吞吐优势。

## 6. 其他方向比较

| 方向 | I=4 前景 | 主要代价/限制 |
| :--- | :--- | :--- |
| **4-bit 叶摘要 + 并行备用校验读** | 已有本文算法与周期模型支持；推荐优先验证 | 新增 2048-bit FF，提前 TT 地址路径及摘要校验，需新规格/RTL/STA |
| L3 改为单份 1R1W，保留插入 E4 提交 | 能解除 E4 的物理 R/W 冲突，但单独改端口不足以完成设计 | 须重做同沿提交/准入、head/cache/bank 视图和数据转发；ASIC 宏成本另计 |
| 全部 L3 改为组合读取寄存器 | 可研究缩短同步依赖 | 8192-bit SRAM 改为寄存器，加上大范围组合选择；时序和面积代价通常更值得警惕 |
| 仅热点缓存、按数据提前完成 | 特定流量可能接近 f/4 | 缓存 miss 和最坏备用路径仍需较长排程，不能作为全部合格流量的固定 I=4 保证 |
| 延迟 L3 物理写回、增加 pending 队列 | 可能重新安排端口，尚需完整证明 | 新逻辑视图转发、写序保证、非整齐输入间隔下的端口仲裁与写回期限更复杂 |

单份 1R1W 存储不等于两份副本；例如 AMD FPGA 的 simple dual-port RAM 支持独立读写，但同址读写仍有 collision 语义，不能省略旁路及具体宏行为核验。参见 [AMD UG573：Simple Dual-Port Block RAM](https://docs.amd.com/r/en-US/ug573-ultrascale-memory-resources/Simple-Dual-Port-Block-RAM) 和 [Address Collision](https://docs.amd.com/r/en-US/ug573-ultrascale-memory-resources/Address-Collision)。这只能说明替代端口类型可存在，不能证明当前目标工艺/器件的面积或时序收益。

| 摘要故障定向注入 | E2 发现备用叶 MAX 与摘要不符，在 NEXT 读和新提交前触发模型断言 |

模型复用了既有容量/链表参考与存储检查，显式重写了 I=4 的阶段调度和摘要更新。同步读结果仍延迟到下一沿才能消费；摘要为独立模型状态，不通过即时读取完整 L3 来绕过依赖。

验证范围是算法、周期、端口及模型状态一致性。故障注入只验证摘要校验的逻辑位置，不是完整 RTL fault 控制；也未验证 RR、初始化摘要扫描、全部参数组合、门级 RAM、完整 F01–F34 或 STA。

## 8. 建议

**f_clk/4 值得作为下一版的候选目标，优先采用“每叶 4-bit 最大索引摘要 + 备用叶并行校验”方案。** 它保留 L1/L2 单份寄存器、L3 单份同步单端口 SRAM、现有 TT/RC/NEXT 数据组织，以及提交早于下一次接受的时序性质。

实施前应将摘要不变量、读写端口、初始化、fault=2 的校验项、FAST4 阶段常量和验证要求写入后续规格。现有阶段 1 的 Matcher、RAM 和复位模块可以复用；新增摘要寄存器及其更新/校验路径，并扩展初始化接线。随后先验证 Trie 子系统，再把 I=4 贯通至准入、链表提交和写回控制。

最终是否选择 FAST4，以相同目标工艺/器件、PVT、宏和约束下的实际 `f4/4`、`f5/5`、`f6/6` 为准。
