## 1. 确认结论

**L2 两个完整副本、L3 三个完整副本不是 Trie 算法、备用路径或固定时延的必要存储开销，也不是 R1 明确提出的要求。**

它们是 V1 选择“A/B/C 三候选同时展开、L2 同拍两读、L3 同拍三读”后，再使用单读口 RAM 复制来满足带宽的工程选择。该方案能工作，但其正确性及端口可实现性不证明复制是必要的。

进一步核查发现，在 V1 现有的 8 拍发射间隔下，可以通过提前读取精确路径、仅访问唯一有效备用叶节点的排程，使用：

- L1 一份状态。
- L2 一份状态。
- L3 一份状态、一个同步读写端口，每拍至多读或写一次。

仍可保持插入 E7 提交、E9 退休，出队 E1 提交、E2 退休及下一事务最早 E8 接受。

因此，将 L2×2/L3×3 固定为 V1 必选资源属于过度约束，建议在下一次规格修订中删除该强制要求并同步更新搜索排程。

## 2. R1 的存储规模与本项目差别

R1 明确给出的单棵 Trie 数据规模为：

| 层级 | 节点数 × 节点位宽 | 状态位数 | R1 描述的实现 |
| :--- | :--- | ---: | :--- |
| L1 | 1 × 16 | 16 bit | 寄存器 |
| L2 | 16 × 16 | 256 bit | 寄存器 |
| L3 | 256 × 16 | 4096 bit | 单端口片内 SRAM |
| 合计 | — | 4368 bit | 上两层共 272 bit，底层 4 kbit |

这里没有说明应保存两份 L2 或三份 L3 的完整内容。R1 中“主搜索和备用搜索并行”也不能直接等同于“完整状态存储复制”。

需要区分：

1. **多个组合读选择器：** 同一组寄存器可以扇出到多个 mux/matcher，增加的是读逻辑、布线及可能的输出寄存器，不必复制整组状态。
2. **存储分 bank：** 不同 bank 保存不同节点，不等于每个 bank 保存一份完整镜像；单端口小 bank 的集合也不等于一块单体宏。
3. **存储副本：** 同一组节点被完整保存多次，写入广播，目的是增加并发独立读带宽。
4. **epoch bank：** 本项目两代标签的 Trie 保存不同业务状态，属于功能分区，不是读副本。

R1 的实现章节还描述树底层由多个小存储块构成，但所给 Markdown 缺少完整图示及逐拍控制细节。因此不能由该资料反推出作者所有备用路径的物理访问安排，也不能声称下述替代排程就是论文原实现。

可以确定的是：R1 的文字和位数并不支持把完整复制 L2/L3 作为其算法要求。

## 3. V1 为什么产生这些副本

现有 V1 把新 tag 表示为 x={a,b,c}，将前驱分成：

- A：相同 a、b，最后 literal 小于等于 c。
- B：相同 a，第二 literal 严格小于 b，剩余部分取最大。
- C：第一 literal 严格小于 a，剩余部分取最大。

现排程在 E1 同时读 L2[a] 和 L2[aC]，在 E2 同时读 A/B/C 的三个叶节点，于 E3 按 A>B>C 选择。

**保持这一逐拍排程不变**时，需要解决 L2 的两读和 L3 的三读带宽；复制是其中一种办法。即使如此，L2 使用小规模寄存器加多个读 mux，也不必保存两份状态。

更重要的是，三个候选不必全部读到底层：

- A 命中后无需 B/C。
- A 未命中、B 的父 marker 存在时，B 对应叶必非空，B 必定优于所有 C。
- 只有 A 未命中且 B 不存在时才需要 C。

因此 A 之外最多还需要读一个备用叶节点，而不是把 B、C 都读一遍。

## 4. 无副本的固定周期替代方案

### 4.1 提前读精确路径

输入 tag 直接给出以下三个地址：

~~~text
L1[bank]
L2[bank,a]
L3[bank,a,b]
~~~

读取这些地址不依赖上层 matcher 结果。上层结果用于验证候选有效性和选择备用路径，不是精确路径地址生成的前置条件。

因此可以在 E0 并行发出三个读取，每个层级仍然只进行一次读；所有 RAM 保持同步 Read Latency=1。

E1 捕获精确路径的 root、parent、leaf 旧值及 A 的结果，并保存到事务上下文。旧值也用于 E7 的精确路径更新，不能在后续读取备用节点时被覆盖。

### 4.2 备用路径选择

~~~text
在 E0→E1 周期分别计算：
    A  = LE(L3[bank,a,b], c)，带父路径有效性
    bB = LT(L2[bank,a], b)，带根路径有效性
    aC = LT(L1[bank], a)

如果 A 命中：
    保存 A，后续备用访问关闭；仍统一到 E3 发 TT 读取。
否则如果 bB 有效：
    备用叶地址 = [bank,a,bB]。
否则如果 aC 有效：
    E1 读取 L2[bank,aC]；
    在 E1→E2 周期求 bC=MAX(L2[bank,aC])；
    备用叶地址 = [bank,aC,bC]。
否则：
    无同代前驱。

E2 只读选定的一个备用 L3 叶。
E3 对备用叶求 MAX，输出最终同代前驱或无前驱。
~~~

备用叶非空依赖 V1 已有的不变量：

~~~text
L2[bank,a][b] == OR(L3[bank,a,b])
L1[bank][a]   == OR(L2[bank,a])
~~~

无同代前驱时，仍按 V1 规则接到旧 epoch 的尾部或成为全局头；此处理不需要新 Trie 端口。

### 4.3 插入逐拍安排

| 沿 | Trie 访问与处理 | 后续路径 |
| :--- | :--- | :--- |
| E0 | 同时读 L1[bank]、L2[bank,a]、L3[bank,a,b] | 同时读 RC、FREE，与原容量预留规则一致 |
| E1 | 保存精确路径旧值和 A 结果；必要时读 L2[bank,aC] | 保存 aC/bB 等候选状态 |
| E2 | A 未命中时，读 B 或 C 中选定的唯一备用叶 | A 命中/无前驱时可关闭该读 |
| E3 | 确定最终前驱 | 发 TT 读取；跨代尾/无前驱继续用已有分支 |
| E4 | 无 Trie 访问 | 读取 NEXT[p] |
| E5 | 无 Trie 访问 | 构造新节点、链路和 bank/cache 更新 |
| E6 | 无 Trie 访问 | 检查并锁存提交描述符 |
| E7 | 必要时写 L1/L2/L3，各一次 | 逻辑提交，其他 RAM 写入同原规格 |
| E8 | 当前事务无 Trie 访问 | NEXT[p] 写回；下一事务可以接受 |
| E9 | 当前事务无 Trie 访问 | 退休 |

E1/E2 的分支只控制读 enable 和选择，不改变 E3/E7 的统一时刻，因此仍为固定时延。

该安排没有取消原 E5/E6 的计算和检查寄存阶段，也没有增加 RAM 倍频、异步读或不可见多读端口。

### 4.4 出队与跨事务冲突

出队继续在 E0 并行读取精确路径和下一头，E1 更新精确路径及其他状态，不增加出队周期。

| 层级 | Insert 最坏访问 | Extract 最坏访问 |
| :--- | :--- | :--- |
| L1 | R:E0；W:E7 | R:E0；W:E1 |
| L2 | R:E0、E1；W:E7 | R:E0；W:E1 |
| L3 | R:E0、E2；W:E7 | R:E0；W:E1 |

当下一事务从全局 E8 开始：

- 前一插入对 Trie 的最后写沿为 E7，早于下一事务的 E8 精确路径读取。
- 前一出队对 Trie 的最后写沿为 E1，更早完成。
- E8～E9 的旧事务重叠仅保留既有 NEXT 写回/退休活动，不占用 Trie 端口。

所以每层均可满足真正的 **1RW：每拍至多一次读或一次写**。这比“允许同拍一读一写”的 1R1W 更严格。

NEXT 的同拍读写风险仍然存在，其 1R1W 和转发机制继续保留。不能从 Trie 可单端口推导出所有存储器都可以取消并发读写支持。

### 4.5 精确路径快照为什么有效

在当前 8 拍发射规则下，一个事务从接受到逻辑提交之间没有其他队列事务提交：

- 前一事务已在本事务接受之前逻辑提交，其 Trie 写入也已完成。
- 下一事务最早在本事务 E8 接受，而本事务已于 E7 提交。

因此 E0 读取、E1 保存的精确路径位图在 E7 更新时仍是正确旧值；把读取提前不会引入共享叶/父节点的丢失更新。

如果将来允许多个尚未提交的查找重叠或缩短发射间隔，应重新分析快照依赖和写端口预算，不能直接沿用这一证明。

## 5. 资源差异

以下均包含本项目的两个 epoch bank：

| 层级 | V1 现有位数 | 单副本位数 | 减少 |
| :--- | ---: | ---: | ---: |
| L1 | 32 | 32 | 0 |
| L2 | 1024 | 512 | 512 bit |
| L3 | 24576 | 8192 | 16384 bit |
| Trie 总计 | 25632 | 8736 | **16896 bit = 2112 B** |

按 V1 相同的存储数据位统计口径，全部表/RAM 从 492,576 bit 降为 475,680 bit，约从 60.13 KiB 降至 58.07 KiB。

这不是芯片面积或实际 BRAM 使用量的保证：L1/L2 采用寄存器时应按寄存器资源计，SRAM/BRAM 有宏粒度开销；提前读取还需要保存相应流水快照。上述数字排除了这些实现开销，与 V1 原估算口径一致。

建议的存储组织为：

- L1：两代共 32 bit，一份寄存器状态。
- L2：两代共 512 bit，一份寄存器状态，配同步读出的选择逻辑。
- L3：两代共 8192 bit，可组织为一份 512×16 单端口同步 SRAM，或两个各 256×16 的 epoch bank；两者都不是镜像副本。

L1/L2 仍可保持对下游一拍读取契约，并不要求改为跨级组合穿透。

## 6. 检查结果及建议修订范围

运行：

~~~powershell
py -3 model/wfq_trie_single_copy_check.py
~~~

本轮结果：

- 71 组集合 × 4096 个查询 × 2 个 bank，共 **581,632** 次查询，与独立排序集合前驱一致。
- A/B/C/无前驱均有覆盖；分别为 277,464 / 209,644 / 70,726 / 23,798 次。
- 每次读取带有最早可使用边沿检查，未在一拍返回之前使用数据。
- 遍历相邻两笔和三笔事务，共 4+8=**12 种** I/E 操作组合，Trie 每层均满足 1RW；其他存储满足 V1 的 1R1W 上限。
- 校核存储位数与减少量。

这是算法、读取依赖和访问排程检查，不是完整 RTL 仿真；尚未验证真实宏延迟、组合路径 Fmax、布局和门级故障行为。

若采纳，需要同步修订 V1 第 1.4、5、6.1～6.3、7.4、10.2、10.5、11 的相关描述及验证条目，明确早读快照、备用叶选择和新的端口表；附录 C 的原检查应保留为历史记录并增加新检查。项目说明中关于强制副本的摘要也需随基线一起更新。

本次核查的结论是：**应将完整副本视为一种可选带宽实现，不能继续宣称其为当前功能与固定提交周期所必需。**
