在项目根目录运行：

```powershell
py -3 -B scripts/run_stage4.py

py -3 -B scripts/run_stage2.py --quick
py -3 -B scripts/run_stage1.py --quick
```

工具为项目本地 Icarus Verilog 13.0，编译模式为 `-g2001 -Wall`。脚本不下载工具、不修改系统 PATH；以编译状态、warning 检查、仿真进程状态和明确 PASS/FAIL 判定结果。第四阶段输出位于 `build/stage4/`，包括逐项编译/运行日志、工具版本、`results.json` 和 27 个输入源文件的 SHA256。运行先标记 RUNNING，失败标记 FAIL，全部通过后标记 PASS。

第四阶段 `--quick` 将每组随机段由 15,000 周期缩至 1,000 周期；满容量定向序列、故障、复位和配置拒绝保持不变。本报告中的第四阶段结果来自完整运行，不是 quick。随机激励周期数不是已接受操作数。

## 3. 状态所有权与排程

单份 L1/L2 组合读寄存器、单份 L3 同步 1RW，以及单份 TT/RC/FREE 同步 1R1W 保持原实现。新增 DATA/NEXT 各只有一个同步 1R1W 实例，按 MEM_DEPTH 定义深度，不进行初始化全清。两个执行/写回上下文保存事务状态和描述符，不复制节点 RAM。

资源模块独占容量、epoch 身份和 bank count、RR、响应队列；元数据模块独占 Trie/TT/RC；链表模块独占链路、cache、bank head/tail/min/max 和 pending。默认链表描述符为 69 bit 的 `{payload,n,p,successor}`，其中 payload=37 bit、n=10 bit、两个 link 各 11 bit；字段由局部常量派生。

| 边沿 | 插入 | 出队 |
| :--- | :--- | :--- |
| E0 | 接受请求、预留 FREE 地址，读取 RC/精确叶 | 保存旧头，预留响应信用，读取 next-head DATA/NEXT 及旧键 RC/精确叶 |
| E1 | FREE 返回、精确快照检查、必要备用叶读取 | 同一许可下更新 metadata/list/cache/bank/count、释放旧地址并生成完整响应 |
| E2 | TT 读取 | 写回完成，释放上下文 |
| E3 | TT 前驱直接驱动 NEXT 读取，捕获描述符主体 | — |
| E4 | NEXT q 直接补齐 successor，原子提交并保存最终 pending | — |
| E5 | 物理修补 NEXT[p]；可接受新请求 | — |
| E6 | 旁路交接完成，清 pending 并释放上下文 | — |

E3 主体暂存旧头，E4 再用 NEXT 返回补齐后继，没有增加完整描述符流水级。无同代前驱的新代插入使用旧代尾作为全局前驱；同键插入使用 TT 的同键尾，保持 FCFS。E4 更新 head cache.next 的逻辑效果立即可见，不能等 E5 才更新 cache。

E5 清除 `patch_pending`，但 pending 的逻辑 NEXT 写仍保留到 E6。E5 新出队的读请求与旧插入的 NEXT[p] 物理写同址时，RAM 封装在读请求沿捕获旁路值。E6 可以同时清旧插入 pending 和建立新出队 pending；两个位掩码独立合并。busy 覆盖完整上下文生命周期；idle 还检查响应和 fault，不要求已提交队列为空。

### 4.1 检查内容

- 每个采样沿核对资格、RR、响应信用、接受间隔、固定提交/修补/写回时刻、context 归属、容量守恒、bank count、响应顺序和稳定性。
- 每次逻辑提交后检查全部 live 节点的 DATA、逻辑 NEXT（物理 RAM 加合法 pending overlay）、全局 head/tail/cache 和 bank 边界，确认链表与独立排序模型一致。
- 每个 E5 物理修补沿核对实际 NEXT RAM 目标字，验证后续撤销 overlay 后不会暴露旧内容；同址读写时核对读返回值。
- 核对 RC/TT/精确叶的提交地址及写条件。每次提交检查 L1/L2 和改变键的 RC/TT/L3；每 257 次提交、定向排空和最终结束时扫描全部 8192 项 TT/RC 及 512 项 L3。
- 检查 L3 读写互斥、DATA/NEXT 的固定写沿与数据、最早响应消费沿和 busy/idle。最后核对所有接受已提交、所有响应已消费、FREE 恢复为全部物理地址的无重复集合。

### 4.2 定向场景与随机范围

定向序列包含 tag 0/4095、乱序插入、同键 FCFS 及出队后重插、A/B/C 搜索、兄弟 marker 保留、head 后插入、NEXT RAW、65535/0/1 跨回绕与第三代保持、两槽响应背压、旧响应等待时空队列任意 epoch 重建、同键满容量、全地址回收重用，以及跨 bank 共用容量。两 bank 填充序列使用 tag=1024/2047/4095，确认 metadata 地址未按节点地址宽度截断。

随机段包含热点/极值/一般 tag、两代及超窗 epoch、多 Flow ID、请求间隙、保持至接受的随机请求和每段 23 周期的随机响应背压。四组均检查完全部已接受事务后排空，不以固定仿真时长截断未完成事务。

这些结果覆盖了 F01～F11、F13～F24、F27、F31～F32、F34 的相关场景，但本阶段不宣布全部 F01～F34 最终验收完成。F12/F19 的所有特定重插变体、F26 的全部 2/3/4 操作组合、F28/F29 的完整边界矩阵仍需在第五阶段形成明确逐项覆盖证据；本次混合流量不能代替组合穷举。F25 的 PIPE6 对比和 F30 的综合/STA 尚未实施。

## 5. 跨域故障、NULL 与运行中复位

`tb_wfq_engine_faults` 每个故障场景重新进行真实顶层初始化，建立 20→30→40 的存活链表和一项尚未消费的旧响应，再注入实际 RAM、寄存器、返回有效位或归属位。正常顶层没有新增 fault_inject 接口。

| 配置 | 故障场景 | 边界复位 | NULL 指针位忽略 | 检查次数 |
| :--- | ---: | ---: | ---: | ---: |
| 10/1024 | 23 | 5 | 1 | 1,198,316 |
| 11/1024 | 30 | 5 | 1 | 1,535,534 |

53 个场景包括跨配置重复执行，不能解释为 53 种独立故障类型。

| 故障类别 | 注入及预期 |
| :--- | :--- |
| RC，code=1 | 插入溢出、出队零计数 |
| metadata，code=2 | TT invalid、精确叶 marker 缺失 |
| 链路/cache，code=3 | cache 无效、非单节点头的 next 为 NULL、返回 next-next 与剩余数量矛盾 |
| epoch，code=4 | 当前缓存或 next-head DATA 的完整 epoch 错误 |
| 容量，code=5 | 出队释放时 FREE 写索引越过容量；同时存在其他错误时取较小编码 |
| 调度，code=6 | DATA/NEXT read_valid 缺失、context 错配、主体/pending 缺失、上下文 phase/committed 损坏、metadata deadline 错配、NEXT 双写意图 |
| 指针，code=7 | 较宽配置的 FREE、TT、NEXT 返回、pending p/n、cache next 和释放指针越界 |
| 同沿与首次错误 | RC=1 与 cache=3 同沿取 1；link=3 与响应信用=5 同沿取 3；后续 code=1 不覆盖先前锁存编码 |

11/1024 配置分别向 FREE、TT、NEXT 的实际读取位置注入 1024、1535、2047，确认在缩窄地址前报 code=7，节点读使能及所有相关写使能关闭，没有别名写入。默认 10/1024 无非法节点指针编码，单独检查 FREE 的较宽计数/索引 code=5。

每个故障采样沿前验证 ready、公共 cycle_allow、commit_fire 和各域写使能撤销。对注入后的全部 TT/RC/L3、L1/L2、DATA/NEXT/FREE 及链表/cache/bank/容量/响应状态保存快照，检查该沿和后续沿没有额外部分更新。已有响应的 valid 和完整 payload 保持，fault 后仍可消费；消费不再次释放节点。错误影响下的在途预留可以保持到复位，不尝试回滚后继续运行。

NULL 专项把尾节点 NEXT 设为 `{valid=0,ptr=全1}`，随后插入并出队，验证 ignored ptr 不触发越界、不参与 NULL 语义比较，也不被解引用。该检查同时在默认及较宽配置运行。

复位分别施加在插入 E4/E5/E6 前及出队 E1/E2 前，验证提交/响应/ready/busy 异步清除，重新执行完整初始化后能够接受并完成新的插入/出队。DATA/NEXT 不依赖复位清 RAM；旧 valid 和 metadata 清除使旧内容不可见。

## 7. 下一阶段的验收边界

当前交付是 FAST5 完整功能 RTL 及第四阶段验证，后续仍需：

1. 建立 F01～F34 的逐项验收矩阵，补齐定向变体、全部连续操作组合及端口/旁路覆盖；PIPE6 相关项保持未实现状态。
2. 按规格 §14.4 执行默认容量每配置至少 10 个独立种子、每种子 100,000 次已接受操作；本次每组 15,000 个随机周期远低于最终验收规模。
3. 扩展完整顶层合法参数覆盖，尤其 11/2048、12/4096、16/65536；此前最大容量 FREE/初始化的组件测试不能替代最大容量完整引擎测试。
4. 对目标器件或工艺完成存储映射、综合和 STA，确认实际单份 RAM/端口、同步读延迟、资源成本及 `f_max/5`。本阶段没有宏仿真、形式验证、面积、功耗或实际 MHz 结果。

状态所有权、接口和描述符位段的维护入口为 `RTL_Implementation_Plan.md` §7～§8。规格文件未因本阶段实现而改变。
