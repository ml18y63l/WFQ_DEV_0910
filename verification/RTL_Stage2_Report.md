# RTL 阶段 2 验证报告：FAST5 Trie 与键元数据

日期：2026-09-16。设计基线：`Design_Spec_V1.2.md`。风格基线：`RTL_Coding_Style.md` v1.7。

阶段结论：新增 5 个 RTL 模块通过 Verilog-2001 编译及阶段 2 回归。元数据子系统支持连续每五个时钟沿接受一个请求，插入在 E4、出队在 E1 提交。当前实现 ISSUE_INTERVAL=5；完整引擎和实际工作频率仍待后续阶段验证。

## 1. 交付与复现

新增 `wfq_trie_search`、`wfq_translation_table`、`wfq_tag_refcount_array`、`wfq_metadata_update`、`wfq_key_metadata`，文件位于 `rtl/`，由 `rtl/files.f` 编译。

```powershell
py -3 -B scripts/run_stage2.py
```

工具为 Icarus Verilog 13.0 stable / VVP，编译使用 `-g2001 -Wall`。9 项合法仿真配置全部通过，编译无 warning；4 项配置拒绝检查通过。全部 13 个 RTL/include 文件通过机械风格检查。

逐用例日志、工具版本、参数和源文件 SHA256 位于 `build/stage2/`。`results.json` 的本次状态为 PASS、quick=false。

## 2. 精确更新组合逻辑

`tb_wfq_metadata_update` 覆盖每一种 16-bit 叶位图的插入/出队计划，并补充随机父/根位图、RC 边界、无效请求、marker 矛盾和较宽指针越界。参考实现根据新 RC 推导 bit 存在性，再逐层聚合，比较写使能及有效写数据。

| PTR_WIDTH / MEM_DEPTH | 检查数 | 结果 |
| :--- | ---: | :--- |
| 4 / 16 | 139,265 | PASS |
| 10 / 1024 | 139,265 | PASS |
| 11 / 1024 | 139,265 | PASS |
| 16 / 65536 | 139,265 | PASS |

总计 557,060 次组合结果检查。最大容量配置验证 17-bit RC 能表示 65536，并从满计数正确递减；没有将 COUNT_WIDTH 绑定到 PTR_WIDTH+1。

## 3. 集成与五拍排程

`tb_wfq_key_metadata` 连接真实 L1/L2 寄存器、单端口 L3、TT 和 RC。参考模型独立维护 live 槽位、插入序号、每键计数和同键尾指针；前驱通过顺序扫描集合求 `max(y<=x)`，不复用 RTL 的 A/B/C 搜索。

| PTR_WIDTH / MEM_DEPTH | 接受请求数 | 实际提交数 | 写禁止搜索探测数 | 状态/结果检查数 |
| :--- | ---: | ---: | ---: | ---: |
| 4 / 16 | 1,088 | 1,084 | 4 | 608,226 |
| 10 / 1024 | 12,934 | 4,742 | 8,192 | 7,135,372 |
| 11 / 1024 | 3,408 | 3,404 | 4 | 1,886,546 |

每组流量逐事务断言相邻接受沿严格相差五拍，包括插入/插入、插入/出队、出队/插入及出队/出队。默认配置的 8,192 次探测是在构造的双 bank 稀疏树上，分别扫描每 bank 的全部 4096 个 tag，使用外部 commit_allow=0 保持树不变；它验证搜索值域和写门控，不是全部可能树状态的穷举，也不计为成功队列提交。

默认配置的插入/探测路径计数为：无前驱 380、A 1471、B 1287、C 7425。所有配置均实际覆盖四种路径。

每个请求都检查：

- E0 的精确 L3/RC 地址和读使能；E1 至多一次备用 L3 读；E2 的 TT 读地址；无前驱时屏蔽 TT。
- E3 之前的前驱 valid、context、bank、tag、ptr、完整 exact 和 path，以及提交主体的 RC 新值。
- 插入 E4 和出队 E1 的提交候选、外部许可、物理写使能/地址/数据，以及沿后 commit_done。
- 每次正常提交后，当前键 RC/TT 与参考相等；每个事务后比较全部 L1/L2/L3，结束时比较 TT/RC 全 8192 项。
- L3 全程不出现同沿读写；无提前 metadata 写、无额外输出寄存器延迟。

定向场景包含 tag=0/4095、两个 bank 的同 tag 隔离、A/B/C 回退、重复键更新尾指针、同叶/同父兄弟保留、最后一项删除、bank 清空后的元数据复用、满容量同键填充和排空。默认配置 RC 达到 1024，TT 能合法指向地址 0，全部 1024 个槽位均在测试模型中分配和释放。混合测试分别追加 1000、2000、1000 次随机操作，并在最后排空。

## 4. 故障、取消与复位

| 配置 | 故障场景 | halt / 全局提交禁止 / 在途复位场景 | 完整存储镜像不变检查 |
| :--- | ---: | ---: | ---: |
| 10 / 1024 | 17 | 6 | 22 |
| 5 / 16（较宽指针） | 19 | 6 | 24 |

故障测试包括 RC 上/下溢、RC 超容量、精确路径 marker 丢失、完整 exact 与 RC 不一致、选中 B 叶为空、选中 C 父为空、有效前驱 TT 无效、分配结果缺失/context 不符、RAM read_valid 缺失、搜索返回归属错误、多个错误同沿选最小编码。较宽指针配置另测分配地址与 TT 指针越界。

测试在故障采样沿前检查 error_valid/error_code、访问抑制和提交抑制，沿后检查 sticky fault、首错保持、request_ready 关闭及 commit_done 不产生。故障/取消前后的全部 TT、RC、L3、L2、L1 镜像相等，确保没有部分元数据写入。缺失 read_valid 时即使 data 呈现为零，也应报告阶段错误 code=6，不能把无效 data 当成 RC 下溢或 marker 错误。

取消测试覆盖 E1/E2/E3/E4 各阶段 halt、E4 撤销外部提交许可，以及 E1 后的在途复位；复位后检查没有延迟写继续落入存储。复位会按设计清除上层寄存器，因此该项单独验证控制取消，不要求与复位前完整镜像相等。

本阶段涉及 fault code=1/2/6/7。链表/缓存、epoch、全局容量和响应信用对应的 code=3/4/5 在后续拥有相关状态的模块中实现与验证。

## 6. 完成边界

当前证据证明 FAST5 元数据域的正确性和五拍发射节奏，没有覆盖完整排序链表、跨 epoch 的全局前驱选择、FREE 栈控制、RR、响应背压、全局提交与两个写回上下文。测试端提供合法的槽位和操作选择，不能替代这些待实现模块的验证。

TT/RC/L3 均只实例化单份数组，L1/L2 为单份 544-bit 寄存器；C 路径的 32 组 MAX 是组合网络。还没有目标工艺综合、RAM 宏映射或 STA 报告，因此当前不承诺 MHz，也不把本域每五拍接受等同于完整引擎已经达到实际吞吐目标。

下一阶段按 FAST5 接入空闲槽管理、epoch 窗口、RR 准入和响应 FIFO。后续 list/commit 集成必须遵守 `RTL_Implementation_Plan.md` §5 的沿前/沿后接口说明，保留旧事务 E5 NEXT 修补和 E6 写回完成所需上下文。
