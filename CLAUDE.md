## Project Overview

Spec-first hardware design project for `wfq_tag_sort_engine`: a fully hardware WFQ (Weighted Fair Queuing) finishing-tag sort/extract module for high-speed QoS packet scheduling. It receives `{epoch, 12-bit finishing tag, flow_id}` descriptors already computed by an external Finishing Tag Computation Block, keeps them in a stable sorted order, and pops the minimum on request.

**Current state: Stages 1 through 4 FAST5 RTL are complete.** See `RTL_Implementation_Plan.md` and `verification/RTL_Stage4_Report.md`. Nineteen modules now include the full `wfq_tag_sort_engine`, single-copy DATA/NEXT, list/head cache, two execution/writeback contexts and global atomic commit/fault integration. Current transaction controllers implement only ISSUE_INTERVAL=5, as requested; passing 6 is explicitly rejected until PIPE6 is implemented. Run `py -3 -B scripts/run_stage4.py` for full-top directed/random/fault/reset regression, `py -3 -B scripts/run_stage3.py` for resources, `py -3 -B scripts/run_stage2.py` for metadata, `py -3 -B scripts/run_stage1.py` for foundations, or `py -3 -B model/wfq_v12_check.py` for the separate specification model. All RTL regression uses strict Verilog-2001. Full-engine five-edge issue and E4/E1 commits have been verified in cycle simulation. Final acceptance-scale random testing, complete F01–F34 evidence, target memory mapping, synthesis and STA remain Stage 5 work. There is no measured maximum frequency or area result.

All design documents are written in **Simplified Chinese**; keep that language for spec/note edits. Reference papers in `Paper_in_Markdown/` are transcriptions with missing tables/figures/formulas — never use their reported performance numbers as measured results for this design (Design_Spec_V1.2.md §1.3).

**RTL language is mandatory: Verilog-2001 (IEEE 1364-2001), not SystemVerilog.** Use .v source files and .vh includes. Use reg/wire, fixed-width vectors, module-local constant functions, assign/always @(*) and clocked always blocks. No SystemVerilog types, structs/packages/interfaces, always_comb/always_ff, casts or array ports. Derive ADDR_WIDTH and COUNT_WIDTH as internal localparams using wfq_clog2; do not depend on $clog2. Baseline testbenches use Verilog procedural checks, with Python reference models permitted; they must not require SystemVerilog mode.

**Coding style is mandatory: read `RTL_Coding_Style.md` before changing RTL.** Apply its file headers, one-module-per-file rule, column alignment, unindented module-body scope, signal locality, asynchronous low-active reset and `_d` / `_d1` suffix conventions. The user's Verilog-2001 requirement is stricter than the style document's generic "2001 or later" allowance. `scripts/check_rtl_style.py` checks a mechanical subset, not the whole design. `rtl/files.f` lists implemented modules; add each real module and its tests as stages progress. Keep downloaded tools in ignored `.tools/` and generated regression output in ignored `build/`.

**Lifecycle terminology:** use “写回完成” / “writeback complete” for completion of RAM writes plus read-bypass handoff and context release. Use INSERT_WB_DONE_LATENCY / EXTRACT_WB_DONE_LATENCY and E_WB in new specifications/RTL. This event is distinct from logical commit and from the last physical RAM write; keep the specified cycles unchanged.

## Architecture Big Picture

The module combines four cooperating structures:

- **3-level multi-bit Trie** (12-bit tag = 3 × 4-bit literals, 16-way branch, one 16-bit bitmap per node): finds the largest live same-epoch key ≤ the incoming tag. L1/L2 use one register copy, read latency 0; L3 uses one true 1RW synchronous SRAM, read latency 1. Read the exact leaf at E0, then at most one fallback leaf using A > B > C priority (§7). FAST5 computes each L2 word's MAX in parallel combinational logic, then selects the C candidate; PIPE6 registers aC before selecting/encoding its L2 word. No state mirrors or variable-depth backtracking.
- **Translation Table (TT)**, addressed `{bank, tag}`: points to the *tail* (most recently inserted) node of each duplicate-key group, giving FCFS among equal tags.
- **Reference Count (RC)**, addressed `{bank, tag}`, default 11-bit (must represent 1024): decides when the last of a key leaves and Trie markers/TT must be exactly cleared (never clear on first-of-group dequeue).
- **Singly linked sorted list** (separate DATA and NEXT RAMs) + **free-slot stack** + **head cache**: minimum is always the global head; extract reads only the head cache, so dequeue logic commits 1 cycle after acceptance.

**Epoch/bank scheme for tag wraparound**: a 16-bit epoch rides with each descriptor; `bank = epoch[0]`, two banks hold adjacent generations, and one global list keeps the entire old-generation segment before the new-generation segment (a new generation's tag 0 attaches after the old generation's tail). Only two generations may coexist; a third is backpressured. TT/RC/Trie are all per-bank.

**Capacity and pointer contract** (§2, §6): MEM_DEPTH is independent of PTR_WIDTH; supported depth is a power of two in 16..65536 and ADDR_WIDTH=clog2(MEM_DEPTH)<=PTR_WIDTH. Default nodes use 10-bit RAM addresses, 10-bit pointer fields and 11-bit capacity counters. All 1024 pointer encodings are valid node addresses; link vector retains a separate valid bit (11 bits total). Default pointer field has no bit 10 or binary out-of-range encoding, so its range comparison can fold away. Retain pre-narrowing stack-index checks (fault_code=5) and range checks for wider-pointer configurations (fault_code=7). DATA/NEXT/FREE have exactly 1024 logical rows; TT/RC remain 8192 rows. Derive COUNT_WIDTH from MEM_DEPTH, not pointer width; size arrays by MEM_DEPTH.

**Fixed-latency transaction model** (§10, §11): one shared issuer, at most one accepted request per I cycles, with I=5 by default or I=6 at elaboration. At most 2 execution/writeback contexts. Insert: E0 accept → E_(I-1) commit → E_I predecessor NEXT patch → E_(I+1) writeback complete. Extract: E0 accept → E1 commit → E2 writeback complete. Prepare the commit descriptor body early; complete successor-dependent fields from NEXT q in the cycle immediately before commit. Do not add a full-descriptor register stage before commit. Pending logical writes and same-edge read bypass preserve atomic visibility; specifically cover the preceding insert's NEXT patch overlapping an extract's next-head read. Both intervals have explicit port and pointer-lifetime proofs; arbitrary interval changes require a new design.

At a common frequency, maximum aggregate throughput is f/I; balanced insert-plus-extract packet service is f/(2I). Compare actual synthesized f5/5 and f6/6 rather than assuming FAST5 always wins at different achievable frequencies.

Planned RTL module decomposition (spec §5.2): `wfq_tag_sort_engine.v` top, plus `wfq_admission_ctrl`, `wfq_epoch_ctrl`, `wfq_trie_upper_regs`, `wfq_trie_search`, `wfq_matcher16`, `wfq_translation_table`, `wfq_tag_refcount_array`, `wfq_list_manager`, `wfq_free_slot_stack`, `wfq_commit_ctrl`, `wfq_sync_ram_1rw`, `wfq_sync_ram_1r1w`, `wfq_response_fifo`, `wfq_init_ctrl`.

## Working Rules for This Repo

Stage 4 integration: `wfq_commit_ctrl` owns two valid/type/age/committed contexts and produces raw E4/E1 commit, E5 patch and E6/E2 writeback deadlines. `wfq_list_manager` owns DATA/NEXT, global/cache/bank boundaries, one uncommitted workspace, E3 body and two final pending vectors `{payload,n,p,successor}`. It completes successor-dependent fields directly from synchronous NEXT q at E4, without another descriptor stage. E5 clears physical patch_pending, but pending_valid and its logical NEXT overlay remain through the E6 read handoff; E5 may reuse the workspace. Clear-old-WB and commit-new-extract can coincide at E6 and must update separate context bits. Only the full execution/writeback valid mask drives busy; idle also requires no responses/reservations and no fault, but does not require an empty committed queue. One common top reset synchronizer drives all state owners. NULL link pointer bits are ignored in semantic equality and range checking. When metadata suppresses pred_valid due to its own error, do not create a derivative missing-predecessor schedule error that masks its original pointer error. Top regression uses an independent sorted-array/FREE/response model and absolute accept-cycle deadlines; fault regression checks all architectural RAM/register images for same-edge atomic inhibition. See plan §8 for vector layout and lifecycle.

Stage 3 integration: `wfq_resource_ctrl` owns admission/RR/cooldown, one uncommitted resource context, the FREE stack and capacity counters, epoch identities/counts, two response registers/reservations, and a sticky minimum-code fault collector accepting external events. The caller still owns two execution/writeback contexts and bank head/tail/min/max. Feed raw pre-gate descriptor proposals into commit_req at E4 insert / E1 extract; missing/early/wrong-context commits fail before mutation. Feed raw metadata/list/port events into external_error_code. Use cycle_allow for EVERY normal state/RAM mutation, including metadata commit_allow and list/cache/physical writes. Do not feed gated commit_fire back as commit_req, or gate alloc_valid by combinational cycle_allow: this can create feedback and distort error priority. FREE alloc_valid before E1 means returned data, not pointer legality; range error is separately reported and must suppress all dereferences. Previously committed FIFO responses drain after fault/halt; their consumption never frees a node again. Stage 3 active ends at logical commit and cannot substitute for busy or the E6/E2 writeback-completion context lifetime. See implementation plan §7.2 for exact wiring contracts. halt is fail-stop/cancel, not a fixed-latency pause/resume mechanism.

Stage 2 integration: `wfq_key_metadata` owns L1/L2/L3/TT/RC and one uncommitted metadata transaction. Its request_ready is only a storage issue window; global admission adds capacity, epoch, RR and response-credit eligibility. FREE returns alloc_valid/context/ptr before E1. Same-bank pred_valid is available before E3 for a direct E3 NEXT read; a missing same-bank predecessor is resolved externally to an old-bank tail or NULL. Insert metadata body is captured at E3 and written at E4; extract uses RAM q directly at E1. commit_ok is only a local candidate; global commit_allow must suppress all resources on an external failure. commit_fire is the pre-edge gate; commit_done is the post-edge pulse. error_valid/error_code are pre-edge events for global minimum-code selection; fault/fault_code are local sticky status. Invalid RAM returns must not be interpreted as count/marker data. The external list/commit controller retains the old insert's E5 patch/E6 writeback context separately, because the metadata workspace can be reused at E5.
